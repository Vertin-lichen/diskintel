# 签名与分发方案

> 现状：0.3.2 及以前**未做代码签名**。Windows SmartScreen 会对未知发布者的 exe 提示「更多信息 → 仍要运行」，
> 部分杀软启发式会误报（本机构建产物曾出现 VHO:Trojan-* 的泛型告警，与源码无关）。

## 可选路线对比

| 方案 | 成本 | 效果 | 门槛 |
|---|---|---|---|
| 不签名 + SHA256 + GitHub 证明 | 免费 | 不能消除 SmartScreen，但可验证来源与完整性 | 无 |
| [SignPath.io](https://signpath.io)（开源免费） | 免费 | 提供 OV 证书签名；SmartScreen 信誉随下载量累积 | 需提交开源项目申请，人工审核 |
| [Azure Trusted Signing](https://azure.microsoft.com/products/trusted-signing) | 约 $9.99/月 | 云签名，CI 集成好；EV/OV 视验证等级 | 需组织/个人身份验证（个人需 3 年历史或强化验证） |
| 商业 OV/EV 证书（DigiCert/Sectigo 等） | 约 ¥1500–5000/年 | EV 证书传统上能较快建立 SmartScreen 信任 | 需企业资质与 U 盾/HSM |
| 自签名证书 | 免费 | 只对本机/受控机器有效，陌生用户需要先装证书 | 无（不建议公开分发） |

## 推荐路径（按投入排序）

1. **立即**：保持不签名，但在 Release 里放 `SHA256SUMS.txt`，README 写清校验命令，
   并用 GitHub 的 **build provenance attestation**（Sigstore）给发布产物做可验证来源；
2. **短期**：申请 SignPath.io 的开源免费签名（MIT 项目符合条件），CI 里加一步签名；
3. **长期**：如果有公司主体，走 Azure Trusted Signing 或 OV 证书，配合固定发布地址积累信誉。

## 本项目的落地情况

- `tools/build-installer.ps1` 已预留签名参数：`-PfxPath` / `-PfxPassword` / `-CertificateThumbprint` / `-TimestampUrl`；
  有证书时用 signtool 依次签 DiskIntel.exe、DiskIntelCLI.exe、Setup.exe 并 verify；没有证书时打印未签名警告与 SHA256；
- `.github/workflows/release.yml` 在打 tag 时构建、生成 SHA256、上传 Release，并在配置了证书 secrets 时自动签名；
- 未签名版本的 SHA256 会同时写在 Release 说明和 `.sha256` 文件里。

## 用户侧校验（写进 README）

```powershell
Get-FileHash .\DiskIntel-0.3.2-Setup.exe -Algorithm SHA256
# 与 Releases 页面公布的哈希比对
```

- GitHub Attestations：https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations

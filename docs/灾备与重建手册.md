# 灾备与重建手册

> 问题：如果把构建出来的软件全部删掉，能不能快速重建？
> 答案：**能，但有一样东西删了就永远回不来——快照数据。**

## 一、资产盘点

| 资产 | 位置 | 在版本控制里？ | 删了能否重建 |
|---|---|---|---|
| Rust 源码 + 文档 | `diskintel-rs/`（19 个文件，`.git` 仅 342 KB） | ✅ 是 | ✅ `git clone` |
| Python 源码 + 445 项测试 | `磁盘情报系统/` | ✅ 是 | ✅ `git clone` |
| goz 源码 | `goz/`（remote: GitHub 镜像） | ✅ 是 | ✅ `git clone` + `cargo build` |
| goz 二进制（goz.exe / gozd.exe） | `D:\soctftware_new\goz\` | ❌ 否 | ⚠️ 需重新编译或从 release 下载 |
| 建库器 `DiskIntelCLI.exe` | `磁盘情报系统/dist/` | ❌ 被 gitignore | ✅ PyInstaller 重打，约 20 s |
| 发行包 zip | `diskintel-rs/dist/` | ❌ 被 gitignore | ✅ `tools/package.ps1` |
| Rust 工具链 | `D:\Softwareinstallation\rust` | ❌ | ✅ 清华镜像重装，约 54 s |
| crates 依赖缓存 | `~/.cargo/registry` | ❌ | ✅ 镜像重下，数分钟 |
| PyInstaller 虚拟环境 | `磁盘情报系统/.venv` | ❌ 被 gitignore | ✅ `pip install`，约 1 min |
| **快照数据（5 份，9.5 GB）** | `D:\disk-intel-data\snapshots` | ❌ **不在任何仓库** | ❌ **不可重建** |

关键结论：**代码全部可重建（源码总计不到 1 MB）**，真正不可替代的只有快照——它是历史时点的观测记录，删了只能重新扫一遍当下的磁盘，过去的变化就再也算不出来了。

## 二、三种删除场景

### 场景 A：只删构建产物（target / dist / 发行包）

```powershell
cd diskintel-rs
cargo build --release                 # 增量，约 20 s
.\tools\package.ps1 -Version 0.2.0    # 约 40 s
```

**约 1 分钟**。建库器若也被删，先补：

```powershell
cd ..\磁盘情报系统
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install pyinstaller -i https://pypi.tuna.tsinghua.edu.cn/simple
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean diskintel-cli.spec
```

### 场景 B：删掉整个程序目录（保留 git 仓库、工具链、快照）

```powershell
git clone <diskintel-rs 仓库> diskintel-rs
cd diskintel-rs
cargo build --release
.\tools\package.ps1 -Version 0.2.0
```

全量编译（依赖已在缓存中）。实测耗时见 §四。

### 场景 C：近似换机（连工具链、依赖缓存、goz 都删）

按顺序：

1. 装 Rust（清华镜像，约 1 分钟）
   ```powershell
   $env:RUSTUP_DIST_SERVER='https://mirrors.tuna.tsinghua.edu.cn/rustup'
   rustup default stable
   ```
2. 配 crates 镜像（`~/.cargo/config.toml`，内容见本仓库提交历史）
3. 重建 goz（源码仓库 + `cargo build --release`），把 `goz.exe` / `gozd.exe`
   放到 `D:\soctftware_new\goz\`，或用 `DISKINTEL_GOZ` 指定
4. 重建 Python 建库器（见场景 A 第二段）
5. 重建 Rust 程序（见场景 B）
6. 重新做一次性授权（`tools\install-engine-bridge.ps1`，需管理员）

**约 20–40 分钟**，主要花在 goz 编译和依赖下载上。

## 三、唯一不可恢复的东西

`D:\disk-intel-data\snapshots\*.sqlite`（5 份，9.5 GB）。

- 它们记录的是**不同时间点的磁盘状态**，`diff` 的价值全在这里。
- 删了以后 `scan` + `snap` 只能得到"现在"，历史对比永久丢失。
- 建议：把 snapshots 目录纳入定期备份（外置硬盘 / 网盘），这是唯一需要备份的目录。

`D:\disk-intel-data\config.json`（引擎档位等配置）也建议一并备份，但它可由
`diskintel engine profile --profile balanced` 一行重建。

## 四、重建实测（2026-11-13 00:31 真实执行）

从干净目录克隆本仓库并全量编译：

```
git clone <本地仓库> rebuild-test     # 19 个文件，1 s
cargo build --release                 # 40.77 s
合计                                  # 约 42 s
```

产物 8.1 MB，`--probe` 路径推导正常，`--bench` 4.16 ms/帧（与正式发行版一致）。

对照：**首次**构建该工程耗时 11 分 34 秒，差异全部来自 crates 依赖下载
（`eframe` 全家桶）。只要 `~/.cargo/registry` 还在，重建就是 40 秒级。

结论：

| 前提 | 重建耗时 |
|---|---|
| Rust 工具链 + crates 缓存都在，只删了源码/产物 | **约 42 秒** |
| 缓存也没了（要重新下载依赖） | 10–15 分钟 |
| 连 Rust 工具链、goz、Python 环境都没了（近似换机） | 20–40 分钟 |

## 五、如果只是想省空间

不必删源码。按收益排序：

| 目标 | 操作 | 回收 |
|---|---|---|
| `target/` | 随时可删，重建 20 s（增量）/ 数分钟（全量） | 2–3 GB |
| `dist/` | 可删，重建 1 分钟 | ~40 MB |
| `待删除/` | 确认后永久删除 | 12 GB 级 |
| `.venv/` | 可删，重建 1 分钟 | ~30 MB |
| `~/.cargo/registry` | 可删，重建要重新下载 | 1–2 GB |

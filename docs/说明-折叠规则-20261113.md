# 低价值折叠规则说明（2026-11-13）

> 对应实现：`src/lowvalue.rs`（纯逻辑，无 UI / 无数据库依赖）
> 适用版本：原生版 0.3.3 起；单测是规则的契约（`cargo test lowvalue`）。
> 本文回答三个问题：**规则是什么**、**为什么某条结果被折叠**、**怎么关掉或改成自己想要的口径**。

## 0. 一句话版本

检索结果里，命中七类「低价值」形态的行**默认折叠**；折叠**只影响界面显示**，不影响命中总数、排序、
导出，也不影响 MCP / `--json` / SQL 的返回结果——AI 通道拿到的永远是全量数据。

## 1. 七个桶与规则表

| 桶 | 中文 | 触发条件 | 会折叠的例子 | 不折叠的反例 |
|---|---|---|---|---|
| Temp | 临时 | 文件名以 `~$` 开头；扩展名 `.tmp/.temp/.part/.partial/.crdownload/.download`；目录名 `temp`/`tmp` | `~$季度报告`、`D:\tmp\build\out.bin`、`C:\Windows\Temp\error.bin` | `D:\资料\报告.docx` |
| Cache | 缓存 | 目录段 `cache/caches/gpucache/code cache/service worker/cachestorage`；目录段 `.cache`；**应用目录下的** `log/logs`；`SoftwareDistribution\Download` | Chrome `User Data\Default\Cache\data_1`、`C:\Users\me\.cache\pip\…` | `D:\logs\notes.json`（不在 AppData/ProgramData/Program Files 下） |
| Backup | 备份 | 扩展名 `.bak/.backup/.old/.wbk/.asd/.swn`；文件名含「备份/backup」+ 日期；`.~lock.`；`#recycle`；回收站 `$R` 正文 | `项目备份20261113.bin`、`C:\$Recycle.Bin\…\$RABCDEF.bin`、`\\NAS\share\#recycle\a.bin` | `我的备份.docx`（无日期）；`$I…` 索引不算正文 |
| System | 系统 | 扩展名 `.dll/.sys/.drv/.mui/.cpl/.ocx/.tlb/.pdb/.cat/.manifest/.etl/.dmp`；**Windows 目录下**的 `.dat/.bin/.db/.sqlite` | `C:\Windows\System32\kernel32.dll`、`C:\Windows\System32\config\SRUDB.dat` | `C:\Users\me\Documents\data.db`（不在 Windows 目录） |
| Installer | 安装包 | 扩展名 `.msi/.msix/.cab/.appx/.appxbundle`；文件名主干含 `setup/install/uninstall` 的 `.exe` | `D:\下载\VSCodeSetup.exe`、`C:\Windows\Installer\1a2b3c.msi` | `setup.txt`、`安装笔记.md` |
| Rare | 冷门 | 文件有扩展名、但不在常用白名单（`COMMON_EXTS`，77 个）里 | `.pyi/.meta/.map/.dds/.as/.ab/.tga/.o/.obj/.pak` 等 | `.docx/.pdf/.jpg/.zip/.py/.rs/.md/.json` 等白名单格式 |
| Hidden | 隐藏 | 任一路径段点开头（`.git` 除外）；路径含 `AppData`/`ProgramData`/`$Extend`/`System Volume Information`；隐藏/系统属性位（兜底） | `AppData\Roaming\App\state.json`、`D:\proj\.idea`、`C:\$Extend\…` | `C:\Users\me\AppData\Local\Programs\…\Code.exe`（用户装的程序豁免）、`D:\proj\.git\config` |

补充口径：

- **目录**只看路径 / 目录名规则，**不看扩展名**（目录名带 `.jpg` 也不会被当成图片处理）。
- **无扩展名**文件不参与 Rare 判定（`README`、`Makefile`、`LICENSE` 不折叠）。
- `.git` 子树整体豁免：路径任一段等于 `.git` 时直接不折叠，`.gitignore`/`.gitattributes` 这类同名前缀文件不受影响。
- `.pdb` 等开发者文件按需求清单归 System（默认折叠）。

## 2. 判定顺序与优先级（先命中先算）

从高到低：

1. `fold_enabled=false` → **全部不折叠**；
2. `.git` 仓库子树 → 不折叠；
3. `fold_keep_prefixes` 命中的路径（整棵子树）→ 不折叠；
4. `fold_keep_exts` 命中的文件扩展名 → 不折叠；
5. 规则链 **Temp → Cache → Backup → Installer → System → Rare → Hidden**，先命中先返回；
   `fold_rare=false` 时跳过 Rare。

因此：

- `AppData\Local\Temp\a.dll` 是「临时」而不是「系统」；
- 回收站里的 `$R1.dll` 是「备份」；
- `C:\Windows\System32\kernel32.dll` 是「系统」而不是「冷门」；
- `C:\Windows\SoftwareDistribution\Download\update.cab` 是「缓存」而不是「安装包」。

「保留清单」（第 3、4 条）**优先于全部规则**，这是有意的：用户资料不该因为落在缓存目录里就被藏起来。
代价见第 7 节。

## 3. 本次（0.3.3）改了什么

1. 新增 `FoldConfig` / `classify_with()` / `explain()`；`classify()` / `is_low_value()` 签名与默认行为保持兼容。
2. 新增默认保留清单 `DEFAULT_KEEP_EXTS`：备份 / 镜像格式（`wim esd gho iso vhd vhdx qcow2 tar gz tgz bz2 xz 7z rar zip`）
   + 常用文档（doc/docx/xls/xlsx/ppt/pptx/pdf/txt/md/rtf/odt/csv/epub）+ 图片 + 音视频。
   命中后**优先于全部规则**不折叠。
3. `logs/log` 目录规则**收窄**：只有 `AppData` / `ProgramData` / `Program Files`（含 x86）之下的
   `log/logs` 才按「缓存」折叠；用户自己的 `D:\logs` 不再被路径规则误伤（理由：机主盘上存在用户自建日志目录，
   开源后别人的目录布局也各不相同，不能靠"目录名恰好叫 logs"就判垃圾）。
4. `fold_rare` 开关：关掉后 `.pyi` 等冷门扩展名不再折叠（其它桶照旧）。
5. `explain()`：一句话说明「被哪条规则折叠 / 为什么保留」，供 CLI 与 tooltip 使用（界面接线由外壳负责）。

## 4. 怎么关掉 / 自定义（`%APPDATA%\DiskIntel\settings.json`）

```json
{
  "fold_enabled": true,
  "fold_rare": true,
  "fold_keep_exts": ["wim", "iso", "docx", "pdf", "jpg", "png", "mp4", "zip"],
  "fold_keep_prefixes": ["F:\\系统重装备份", "D:\\重要资料"]
}
```

| settings 字段 | FoldConfig 字段 | 含义 |
|---|---|---|
| `fold_enabled` | `enabled` | 总开关；false = 检索页不再折叠任何结果 |
| `fold_rare` | `fold_rare` | 是否折叠「冷门」扩展名 |
| `fold_keep_exts` | `keep_exts` | 保留扩展名；大小写不敏感、可带点（`".PDF"` 等价 `"pdf"`） |
| `fold_keep_prefixes` | `keep_prefixes` | 保留路径前缀；大小写不敏感、正反斜杠等价、按目录段边界匹配 |

> 字段名以设置页实现为准（本文件先按 `fold_*` 命名；若外壳最终字段名不同，只改本文档与映射，规则不变）。

常见用法：

- **完全关闭折叠**：`"fold_enabled": false`。
- **只想让代码备份可见**：`"fold_rare": false`（`.pyi/.meta/.map` 不再折叠，`.dll` 等系统文件仍折叠）。
- **整棵目录保留**：把它加进 `fold_keep_prefixes`（例：`F:\\系统重装备份`）。段边界生效：
  `F:\系统重装备份` 不会误伤 `F:\系统重装备份2`，但会保留 `F:\系统重装备份\...` 全部内容。
- **某类扩展名一律保留**：加进 `fold_keep_exts`（例加 `"pyi"` 后 Python 类型桩不再折叠）。
- 删掉默认保留清单里的某项（如 `"docx"`）会恢复「Office 锁文件也折叠」的老行为。

统计该目录 **224,793 条**（28,677 个目录 + 196,116 个文件），按 HEAD（0.3.2）旧规则：

| 桶 | 条数 | 占比 |
|---|---|---|

| Cache 缓存 | 20,487 | 9.11% |
| Backup 备份 | 211 | 0.09% |
| System 系统 | 4,314 | 1.92% |
| Installer 安装包 | 12 | 0.01% |

`.pyi` 38,565 条、`.meta` 12,193、`.map` 3,154、`.bin` 2,067、`.xsd` 1,683、`.tpl` 1,321、

`.codex` / `.claude` 等点开头目录（`Hidden` 17,308）、`.dll` 等系统扩展名（`System` 4,314）。

该目录的文件构成（按一级子目录，仅文件数）：

### 0.3.3 新默认规则下的同一目录

| 口径 | 折叠条数 | 占比 | 说明 |
|---|---|---|---|
| HEAD 旧规则 | 112,561 | 50.07% | 见上表 |

## 7. 已知边界与代价（重要）

1. **保留清单优先于一切规则**：默认含 `.docx/.txt/.pdf/.jpg/.zip` 等，所以连 `~$xxx.docx` 这种 Office 锁文件、
   回收站里的 `$R…docx`、缓存目录里的文档副本也默认**不折叠**。这是「不误伤用户资料」的代价；
   想清理锁文件，把 `docx` 从 `fold_keep_exts` 移除即可（会恢复 Temp 判定，有单测覆盖）。
2. **目录不受 `keep_exts` 影响**：目录只看路径 / 目录名规则；要保留目录子树请用 `keep_prefixes`。
3. `keep_prefixes` 按**目录段边界**匹配：`D:\备份` 保留 `D:\备份\...`，但不误伤 `D:\备份2\...`。
4. 路径规则仍是「按名字猜」：`D:\cache`、`D:\tmp` 这类用户自建目录仍会被折叠（`logs` 已收窄，`cache/temp` 未动）；
   遇到误伤用 `keep_prefixes` 兜底，并把现象反馈给维护者。
5. 属性位规则（`FILE_ATTRIBUTE_HIDDEN/SYSTEM`）在当前快照永不触发（文件 0 / 目录 16），
   只有将来接实时扫描、传入真实属性时才生效。
6. `explain()` 的输出是给人看的一句话，不是稳定协议；需要机读请解析 `Verdict { bucket, reason }`。

## 8. 为什么 AI / JSON 不受影响

折叠判定只在检索页渲染时使用（`views/search.rs` 调 `classify` 生成 `Option<Bucket>`）。
`--json search` / `--json sql` / MCP 工具读取的是 SQLite 快照本身，不读 `lowvalue` 的判定结果，
所以折叠开关不会让 AI 少看到任何一条记录，也不会改变任何计数（检索页的命中总数、状态栏数字都不变）。

## 9. 维护指引

- 改规则时同步改三处：`src/lowvalue.rs` 的规则函数 → `tests` 模块单测 → 本文档的规则表与真实数据占比。
- 新增桶：`Bucket::ALL` 是 UI 折叠条的唯一数据源（`views/search.rs` 直接遍历），新增后要同时补
  `label()`、规则函数、单测与本文档；否则折叠条会漏展示。
- 单测命令：`cargo test --release lowvalue`（当前 `src/lowvalue.rs` 内 61 条）；
- 规则以外的展示口径（折叠条文案、展开淡色）见 `views/search.rs` 模块文档，不在本文件范围。

## 10. 如何问「这条为什么被折叠 / 保留」

实现提供 `lowvalue::explain(path, is_dir, attributes, &config) -> String`，输出形如：

- `折叠为「冷门」：扩展名极少使用`
- `折叠为「系统」：Windows 系统文件扩展名（.dll/…）`
- `不折叠：扩展名 .docx 在保留清单里（fold_keep_exts）`
- `不折叠：路径在保留前缀「F:\系统重装备份」之下（fold_keep_prefixes）`
- `不折叠：未命中任何低价值规则`
- `不折叠：折叠总开关 fold_enabled=false`
- `不折叠：.git 仓库内容整体豁免`

CLI / tooltip 接线由外壳负责；规则与解释共用同一套优先级，不会出现「解释与结果不一致」。

# 快照执行策略（现状与可选方案）

> 起因：机主问「快照到底是每次启动自动建，还是必须人工创建」。
> 结论：**当前版本只有人工创建**，程序启动不会自动建快照；0.3.2 起增加可选的「启动时自动建快照」（默认关闭）。

## 1. 现在的链路（0.3.1 及以前）

```
人工点击「扫描」
  → Backend::locate 找到 DiskIntelCLI.exe（建库器）
  → 后台线程调用 DiskIntelCLI scan  （goz/MFT 全盘扫描，输出 EFU，约 6-15 s）
  → 后台线程调用 DiskIntelCLI snap --note ...（写入 snapshots/<时间戳>.sqlite，约 60-90 s）
  → 完成后 reload_snapshots()，界面自动切到新快照
```

- 触发点只有三个：工具栏「扫描」、文件菜单「重建索引（扫描并新建快照）」、快捷键（无）。
- **程序启动、切换视图、切快照都不会建库**；也不会定时建库。
- 数据目录里的 `snapshots/index.json` 与 `.sqlite` 只由建库器写入，本程序只读。
- 对比视图依赖至少两份快照；只有一份时提示「至少需要两份快照」。

## 2. 为什么默认不自动建

| 原因 | 说明 |
|---|---|
| 耗时与负载 | 一次建库 60-90 s、写入 1.5 GB，启动即跑会让开机体验变差 |
| 磁盘占用 | 每份 v3 快照约 1.5 GB，一天多次会把盘吃满 |
| 权限 | 建库需要读 MFT/USN，依赖 goz 引擎桥（一次性提权授权），不是所有机器都配好 |
| 语义 | 快照是「某个时刻的证据」，什么时候取应该由用户决定 |

## 3. 0.3.2 增加的两个可选项（默认关闭，用户自己开）

### 3.1 启动时自动建快照

- 位置：工具菜单 →「启动时自动建快照」（勾选即存）。
- 行为：启动后延迟 3 秒（让首帧先渲染），若开关打开且建库器可用，则走与「扫描」完全相同的后台流程；
- **去重保护**：若最新一份快照的创建时间距今小于 N 分钟（默认 60，可在 settings.json 改）则跳过，避免频繁建库；
- 失败不弹阻塞对话框，只在状态栏/提示条显示原因；
- 设置文件：`%APPDATA%\DiskIntel\settings.json`。

### 3.2 检查更新（不自动安装）

- 位置：帮助菜单 →「检查更新…」；**不会自动下载或替换任何文件**，只做版本比对并给出下载页链接。
- 手动热更新：下载新版本 exe/安装包 → 覆盖安装目录（或运行新安装包）→ 数据目录与设置不受影响。

## 4. 储备方案（本期不做，记录备选）

| 方案 | 说明 | 代价 |
|---|---|---|
| 计划任务每日建库 | 用 Windows 计划任务在空闲时跑 DiskIntelCLI，程序不用常驻 | 需要一次提权注册；用户可自行用 schtasks 配 |
| 保留最近 N 份 | 建库后自动把更老的快照移入 `待删除/` | 需要明确的保留策略，避免误删证据 |
| 增量快照 | v4 delta 链（工具已实现），只存变化 | 读路径较慢，等 v4 检索优化后再做默认 |

## 5. 一句话回答

**现在是纯手工**：点「扫描」才建，启动不会自动建；
如果你希望开机就来一份，0.3.2 起可以在「工具」菜单勾选「启动时自动建快照」。

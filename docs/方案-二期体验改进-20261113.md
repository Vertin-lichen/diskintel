# 二期体验改进 · 实施方案（2026-11-13）

> 任务号 T-20261113-09　输入：机主试用 0.3.0 后的 6 组问题
> 原则：先查证事实，再改界面；不掩盖数据口径，而是把口径讲清楚。

## 0. 查证结论（改之前必须先承认的事实）

### 0.1 空间页的 C 盘 320.8 GB 是怎么来的

- 空间视图的**容量与空闲**来自 Win32 `GetDiskFreeSpaceExW`（实时）；
- **已用**来自**快照里所有文件 size 的逻辑和**（不是实时占用）。
- 实测（快照 20261112-100008，C 盘 1,891,728 个文件）：逻辑和 = 344,410,443,068 B = **320.8 GB**；
  同期卷容量 299.1 GB、实际空闲 10.4 GB → 实际已用约 288.7 GB。差额约 32 GB 的来源：
  1. **硬链接重复计数**（WinSxS 与 System32 等同一份数据多个路径）；
  2. **NTFS 元数据文件**被当成普通文件计入（`C:\$MFT` 2.24 GB 等）；
  3. **压缩/稀疏文件**：逻辑大小 > 实际占用（如 Chrome 权重、Android 镜像）；
  4. 快照库本身不保存 Windows 属性位（实测目录恒 16、文件恒 0），**无法还原硬链接与重解析点**。
- 结论：数字不是伪造的，但**口径是「逻辑大小」而非「卷占用」**；UI 直接拿它除以容量并显示 100%，是产品缺陷。

### 0.2 「卷九 9dba3ee0」是什么

- `\\?\Volume{9dba3ee0-…}\` 是磁盘 0 上的 **Recovery 分区（907 MB，无盘符）**，
  不是用户数据卷。空间页把无盘符卷也当卷卡片画了出来，且没有友好名称。

### 0.3 物理盘拓扑（本机实测）

|---|---|---|
| 0 | KINGSTON OM8PGP41024N-A0 · NVMe · 954 GB | C(299)、D(453)、E(200)、Recovery(0.9)、System/Reserved |

### 0.4 检索页「输入不同步 / 回车打开首项」的根因（代码级）

1. `widgets::search_field` 返回的是外框 hover 的 Response，**不是 TextEdit 的 Response**，
   调用方 `response.changed()` 永远为 false，输入变化只能靠 `query != last_applied` 兜底。
2. 兜底逻辑里 `pending_at = Some(now())` 在**每一帧**都重置（只要两者不等），
   防抖计时永远走不到 260 ms → **只有回车才会真正检索**。
3. 回车同时命中两处：`show()` 里「立即检索」+ 全局键盘区「打开选中行」。
   TextEdit 单行控件在回车时会让出焦点，于是同一帧里 `focused().is_none()` 成立 →
   **回车既检索又打开第一行**。

## 1. 空间视图改造（w1-space）

1. **口径分离**：环形图改为「实际已用 = 容量 − 实时空闲」；快照逻辑大小单独一行并给出差值。
   逻辑 > 容量时不再显示 100%/超出容量，改为「实际 88% · 快照逻辑 107%」+ 说明 tooltip。
2. **按物理盘分组**：新增 `space/diskmap.rs`，用 `FindFirstVolumeW` + `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`
   把卷映射到物理磁盘，再用 `IOCTL_STORAGE_QUERY_PROPERTY` 取型号/总线；每个物理盘一行，行首写盘号与型号。
3. **无盘符卷**：Recovery/System/Reserved 归入「系统保留」折叠区（默认收起），不再冒充普通卷。
4. **差异解释**：逻辑与实际的差额 > 5% 时，卡片脚注写明可能原因（硬链接 / 系统文件 / 压缩）。

## 2. 检索视图改造（w2-search + w5-shell）

1. 修复 `search_field` 返回值（w5），`changed()` 立即置 dirty；防抖改为「记录上一次看到的 query」。
2. 回车语义：**只提交检索**；只有用户先用 ↑/↓ 移动过选中行，回车才打开该行。
3. 启动自动聚焦搜索框；`Ctrl+F` 聚焦、`Esc` 清空并失焦、`Ctrl+1..4` 切视图（w5）。
4. **Hero 检索态**：空查询时搜索框居中放大（约 1.35×），首次输入后 180–220 ms 缓动上移到顶部。
5. 搜索历史：最近 20 条，持久化到 `%APPDATA%\DiskIntel\search-history.json`；聚焦且空查询时下拉；
   ↑/↓ 选择、回车应用、`Ctrl+Delete` 清空。
6. 列宽可拖拽（表头分隔条）+ 双击自适应 + 持久化；窄窗口自动隐藏「类型」列并压缩大小/时间列。

## 3. 低价值结果折叠（w3-lowvalue + w2 集成）

新增 `src/lowvalue.rs`：按路径/扩展名/目录名给每条结果打 `Bucket`（临时、缓存、备份、系统、安装包、隐藏）。
检索页默认折叠这些行，列表底部显示「已折叠 N 项低价值结果 · 展开」，展开后原位混排并淡色标记。
四类可单独开关，状态持久化。

## 4. 快照页（w4-snapshots）

1. 每行「删除」按钮：二次确认；删除 = 移入 `D:\disk-intel-data\待删除\<时间戳>_<名>` 并登记 MANIFEST；
   当前快照与最后一份不可删。
2. 备注可编辑：sidecar `snapshots/notes.json`（快照库只读，不写 meta），点击单元格内联编辑，回车/失焦保存。

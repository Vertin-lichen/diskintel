# 0.3.1 改进说明（对应机主试用反馈）

> 反馈来源：2026-11-13 上午试用 0.3.0 后提出的 6 组问题，逐条对应。

## 1. 「空间页 C 盘 100%、320 GB 比盘还大，数据是真的吗？」

**是真的，但口径不对**，详见 [说明-数据口径-20261113.md](说明-数据口径-20261113.md)。

- 旧实现：容量/空闲取实时 API，已用取快照里所有文件 size 的逻辑和 → 两套口径混用。
- 实测：C 盘逻辑和 320.8 GiB（含 WinSxS 硬链接重复计数、$MFT 等 NTFS 元数据、压缩/稀疏文件），
  同期实际已用 265.2 GiB（容量 299.1 − 空闲 33.9）。
- 0.3.1：环形图用实际占用，逻辑大小单列并标注差值，超容量时只写脚注不标红。
- 「卷九 9dba3ee0」= 磁盘 0 的 907 MB Recovery 分区，已收进「系统保留」。

## 2. 「输入不同步、回车才搜索、回车还打开第一项」

根因（代码级）：
1. widgets::search_field 返回的不是 TextEdit 的 Response，changed() 永远 false；
2. 防抖的 pending_at 每帧被重置，计时期满永不成立 → 只有回车才触发；
3. 回车同时命中「立即检索」与「打开选中行」，单行 TextEdit 回车会让出焦点 → 一次回车干了两件事。

0.3.1：输入 200 ms 防抖即时检索；回车只提交检索；回车打开需先用 ↑/↓ 选行；Hero 态 + 启动聚焦 + Ctrl+F。

## 3. 「页面太大、搜索框在最上面不方便；能不能做动效 / 搜索历史」

- Hero 检索态：空查询时居中放大，出结果后 220 ms 缓动收回工具栏（animate_value_with_time + smoothstep，两端严格重合有单测）。
- 菜单栏 30→28、工具栏 40→36；搜索框宽度自适应窗口。
- 搜索历史持久化 + 下拉（↑↓/回车/Esc/删除/清空）。

## 4. 「列宽不能调、小窗口排版差」

- 表头分隔条可拖拽（±4 px 命中区，不抢列头点击），双击自适应，五列各自最小宽度，路径列吃剩余空间。
- 列宽比例持久化；<1000 逻辑像素自动隐藏「类型」列。

## 5. 「空间页按物理盘分行；卷九是什么」

- 新增 views/space/diskmap.rs：卷枚举 → IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS 映射物理盘 → 型号/总线；
  失败逐级降级，绝不空白/panic。
- 本机效果：磁盘 0 KINGSTON（C/D/E）、磁盘 1 Yotta（F）、磁盘 2 Seagate USB（I/J），系统保留折叠。

## 6. 「快照页要能删、备注能自己填」

- 删除：二次确认 → 移入 D:\disk-intel-data\待删除\ + 登记 MANIFEST（不永久删除）；当前/最后一份不可删。
- 备注：单击内联编辑，存 snapshots/notes.json（快照库只读，不写 meta）。

## 7. 「自动隐藏临时/缓存/备份/DLL 等低价值结果」

- 新增 src/lowvalue.rs：6 类判定 + 36 条单测，.git 整棵豁免，用户文档目录下的数据库不误判。
- 检索页默认把低价值行折叠到末尾，底部显示「临时 X · 缓存 Y · 系统 Z …」，点击原地展开（淡色 + 左侧细线）。
- 真实数据：全库 47.1% 条目属低价值；报告查询只折叠 15.3%（原件保留），jpg 仅 6.0%，dll 折叠 96%（符合预期）。

## 9. 快捷键

| 键 | 作用 |
|---|---|
| Ctrl+F / Ctrl+L | 聚焦检索框（任何视图都切回检索） |
| Esc | 清空并失焦（历史下拉开着时先关面板） |
| Ctrl+1..4 | 检索 / 空间 / 对比 / 快照 |
| F5 | 刷新当前视图 |
| ↑ / ↓ | 历史下拉或结果行 |
| Ctrl+C | 复制选中项路径 |
